# Dossier

围绕一个对象组织有价值的历史记录，让读者能还原经过、决策依据、成果与结论，并回到原始材料。卷宗材料可独立交付；调档默认由 breach 展示，渲染不可用时仍可只读返回原档。

## 入口与权限

仅有建档、调档、更新三个模式。人物OSINT是建档内部按对象选择的流程，也供人物档案更新复用，不是独立模式。

| 模式 | 用户表达 | 行为 |
|---|---|---|
| 建档 | 建立/整理 XX 的档案、给人物/作者建档、查这个人、深挖这个作者 | 先查重，再按对象处理：人物走跨平台OSINT，无档案则创建，已有则沿原ID调查更新；主题、项目或事件走材料梳理，已有同范围卷宗则读取返回，未找到才创建 |
| 调档 | 调取/给我 XX 的档案 | 只读定位已有卷宗及其材料，默认交给 breach 档案模式生成包外独立 HTML；用户指定仅原文/路径时按指定交付 |
| 更新 | 更新/补充 XX 的档案 | 定位已有卷宗，增补来源与变更记录，保留被修正的历史结论 |

显式 `$dossier` 未指定操作时，按上下文判断；无法判断时先只读查询。调档未找到时报告范围与候选，不自动转建档；更新未找到时也不另建。主题同名但范围不同、多个候选无法区分时，列出差异请用户选择，继续可独立进行的只读核实。

调档不重建、不刷新、不补写原档，不更新原档访问时间、身份索引、hash 或状态。发现新材料、断链、过时结论，只在本次答复中指出；用户要求更新后才持久化。默认展示生成的 HTML 和渲染回执保存在源包之外，不算创建第二份权威卷宗。用户明确要求仅原文、路径或不生成 HTML 时，跳过渲染。

## 建档中的人物分支（OSINT）

用户说“查这个人”“深挖这个作者”，或明确要求给人物、作者、博主、账号主理人建档时，进入建档模式；明确要求更新人物档案时，仍属于更新模式并遵守指定范围及未找到不另建的边界。两者都读取并执行[人物 OSINT](references/author-osint.md)。调查是过程，建档是结果，不因“建档”或“查人”的措辞改变调查深度；无需重复要求另一种触发词。链接、平台+ID、名字、截图或多条线索都只是入口；调查对象是人物及其公开活动，交付是可追溯的判断。不得因输入是文章就降级为文章摘要、链接堆积或仅整理该平台作品，也不限定经济学领域。

按意图区分，不按“查”字一概排除：仅问“他是谁”“查他的某个职务/某句话”，或要求总结文章，只回答对应问题；单独发链接/ID/名字也不自动建档。“查这个人”则明确授权人物OSINT及结果入档。已明确调查/建档后的名字补充、纠正和重试继续原任务；无需重复索要触发词。只读调档仍按上方规则执行，不自动重新调查。先按下节查重；建档中的人物分支无论使用哪种触发词，已有同范围档案都沿原 ID 调查更新。主题、项目或事件建档保留既有复用规则。

## 存储与定位

从全局指令解析 Canon，读取 `artifacts/dossier-index.json`。统一档案馆根目录使用索引的 `archive_root`；旧索引未记录时读取其 `storage_policy` 或 Canon 中已接受的统一档案馆决策，不从当前 cwd 猜目录。根目录未配置或不可访问时说明缺口，不退回项目仓库另建档案。

新档案默认放 `<archive_root>/dossiers/<project-or-topic>/<id>/`，项目或主题分组沿用馆内目录。工程代码、设计、测试、原始数据仍留项目中；卷宗正文、阶段结论和必要来源快照在档案馆维护。项目里的旧档案若已迁移，只作历史副本；按索引定位新入口，不因切换分支改用旧副本或创建第二份档案。

## 身份与查重

首次使用阅读 [材料包与索引契约](references/material-contract.md)。

1. 先按 ID、scope、标题和 aliases 查 Canon 卷宗索引，读取索引指向的统一档案馆入口。未命中时在 `<archive_root>/dossiers/` 范围内查找，再查 Canon artifact index、关联 task/update card 和迁移映射；旧项目位置仅用于追溯或定位尚未迁移的历史档案，不作为已迁移档案的替代维护入口。已知根目录检索用 scoped `rg --hidden --no-ignore`；不扩成整盘扫描。
2. 身份由稳定 `id`、`scope`、标题及 aliases 共同确定。范围包含项目/对象/边界；日期版本、格式、语言、别名或新的视觉皮肤不产生新身份。先确认 LiDAR/激光雷达等语义别名，再决定是否同一卷，不能只靠关键词相同或字符串不等。
3. 找到旧版主题档案但无新格式 manifest，仍按已有卷宗复用。调档时不自动迁移或登记；建档请求也不借“升级格式”重建。更新模式或建档中的人物分支需要补充旧档时，可沿原ID补元数据；不另建竞争档案。
4. 同范围已有卷宗 → 复用已有 ID/位置；调档以及主题、项目或事件建档返回既有材料；更新模式或建档中的人物分支继续沿原 ID 补充。仅建档模式在确认没有候选后才选新 ID；调档或更新未找到时报告缺口，不创建。创建目录用排他方式，不覆盖现有目录。写入前再次检查索引；多人/多代理同时登记时使用该库现有锁/事务机制，无法安全登记则先保留草稿，不发布第二份权威卷宗。

索引不可读、解析失败或只搜到部分范围，不算“没有重复”。说明阻塞或覆盖限制，不能据此创建竞争记录。

## 建档前：主题全貌与范围

查重后确需建档时，先梳理主题的实际工作线，再决定材料目录，不能把名称中的技术对象直接当作全部范围。沿索引、关联任务、主题目录和别名做初检；根据发现的事件与产物展开，不只搜索对象的同名文件。相关工作可能包括需求与沟通、设计实现、参数与验证、培训与知识交付、发布使用、失败与后续；这些是发现线索，不是每份档案必须填满的栏目。

把初检发现的主要工作线、来源线索和范围边界整理为简短覆盖表，随阅读补全：`主题面/工作线 → 来源与读取范围 → 已收材料或证据缺口 → 未纳入理由（若有）`。表放入口或已有材料中，不另建第二套事实清单。用户明确限定范围时沿该范围梳理；相关但范围外的线索注明排除理由，不借“全貌”扩大授权。

例如项目建档初检发现模型验证、培训课程和发布记录，三条线都要处置；课程已制作、已发布、实际授课分别核实，不能由一种完成状态推断另一种。更新时复核新增或受影响工作线并保留既有范围；局部补充不默认触发整卷重查。只读调档不补写覆盖表，也不因本规则迁移旧卷。

## 来源与材料

材料检索顺序：Canon 卷宗索引 → 统一档案馆材料包 → Canon artifact index / 关联 task/update card → 项目源 artifact → 必要的原始会话 → 外部来源。来源身份、读取范围、事件日期、整理日期分开。搜索命中、存在路径或旧摘要不能替代读取原件。

以原始材料为依据，分清事实、当时判断、后来的修正与未决问题。只读到二手材料时明确标记；找不到原件就保留缺口。历史报告通过不自动变成当前运行状态或验收。

材料按读者问题组织，常见有：概览、决策记录、成果与结论、原话节选、报告、照片/实验图、失败与撤回、未决线索。只收录有价值且有身份的内容，不把搜索结果整堆交付，也不为凑齐类型生成照片或虚构批注。

Thread 用于演变；Tree 用于组成；Graph 用于有依据的关系。按材料选一种或若干，不强制齐全；关系含义由本流程决定，呈现层只负责显示。

起草/实质重写综合文档时使用 `paperwork` 的结构与证据表达规范；忠实读取或交付现成材料时不重新写作。原始来源保留原位置与身份；复制、摘录、转录或可移植打包均标明派生关系，不把副本当独立证据。

## 建档与更新的交付

材料包含可独立阅读的入口文档、实际需要的材料文档/附件引用、来源清单及轻量 manifest。数量与结构服从证据；大文件默认引用，不默认复制。卷宗遵循上述统一档案馆布局；项目布局规则用于定位工程原始材料，不改变卷宗默认存放位置。Canon 只登记身份、关系和 artifact 引用，不另存一份卷宗正文。

引用代码或版本化文档时记录 `repo + commit + path`；未提交材料明确标注工作区截面与 hash。必要小型材料可保存带原路径、读取截面和 hash 的派生快照；大数据、构建包继续引用原位置。迁移时间与研究 `as_of/read_at` 分开，不以迁移或复制升级证据状态。

更新保持同一 ID 与索引指定的维护入口，记录本次新增、修正、替代及来源；新结论不能抹去当时的决定。源文件变化后需重新读取，旧 hash 不能冒充当前验证。正文/证据冲突保留各自日期和适用范围，不能为了叙事顺畅消除差异。

已有索引就复用；没有时，仅在首次授权写入时建立 Canon `artifacts/dossier-index.json`，作为身份与路径目录，不存第二套事实。登记也更新 Canon 主 artifact index 的引用。调档不能创建空索引。

新格式的包交付前运行只读 gate：

```bash
python3 <skill-dir>/scripts/dossier_gate.py <manifest.json> --catalog <dossier-index.json>
```

Gate 校验材料与来源引用、包内路径、索引身份冲突；不检查主题覆盖完整性。语义去重、来源实际已读及结论保真仍需人工/代理核对。旧格式调档不强制通过新 schema，也不为过 gate 改档案。

### 交付前：覆盖完整性复核

发生新建或补充的建档/更新交付前，将覆盖表与初检索引、关联任务和来源目录逆向对照，再从最终材料回查来源：重要工作线是否被遗漏、藏在无入口附件里，或仅因“不像技术核心”而未收录？后续阅读新发现的工作线也须回填覆盖表，不能只核对已经选入的材料。

每条范围内的重要工作线都应有可调阅材料与已读来源，或明确的证据缺口；排除项须有符合用户范围的理由。已发现但未处置的重要线索要先补查；确受来源/权限限制时按实际覆盖范围交付并列缺口，不能称覆盖完整。区分“未找到原件”和“该工作未发生”，保留各阶段及失败/撤回记录。

在覆盖表旁简记本次复核范围、结果与未覆盖项；结构 gate 和覆盖复核分别报告。材料数、来源数、hash/链接检查通过，都不能替代覆盖结论。覆盖结论只针对本次声明范围和已查来源，不声称穷尽全部历史。表的记录约定见[材料包与索引契约](references/material-contract.md)。

## 呈现与收口

建档/更新默认交付材料包与路径。调档默认调用 [Breach Archive](../breach/references/archive-mode.md)：由 dossier 完成定位，将已登记 manifest、身份索引与包外输出路径交给 breach，不重新调查或修改原档。输出默认位于当前工作仓库 `.proposal/archive/<dossier-id>/index.html`，附独立渲染回执；已有派生版本需保留时另选版本目录。交付 HTML 展示入口，同时保留原档链接与证据状态。

渲染使用现有材料、顺序、关系、来源和缺口，不补造事实。遵守 breach 的校验和浏览器检查，核对源包、来源及身份索引在渲染前后不变。用户指定仅原文/路径或禁止 HTML 时只读返回材料；档案未找到、有歧义、缺标准 manifest/登记、校验失败或渲染依赖不可用时，说明原因并交付可读原档（若有），不迁移、补字段、刷新hash、另建或注册档案来绕过限制。默认展示授权只涵盖包外派生产物。

建档/更新遵守共享 [Canon output contract](../../references/canon-output-contract.md)，登记持久结果；调档不写 update card。每次实际执行结束按共享 [telemetry 契约](../../references/skill-telemetry.md)记录本地 outcome，仅记录 skill/runtime/trigger/outcome、artifact/gate 等允许元数据，不记录查询、人物或材料正文。
