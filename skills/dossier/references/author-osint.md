# 建档中的人物 OSINT：从线索到有据判断

“给人物/作者建档”“查这个人”“深挖这个作者”统一进入建档模式的人物OSINT分支：同样调查公开信息、形成判断并入档，不因措辞区别调查深度。查重后无档案则创建，已有则沿原ID调查更新，不只返回旧档。更新模式中的人物档案也沿用本流程，按用户指定范围补充，未找到既有档案时报告缺口、不另建；“调取/给我已有档案”保持原档只读，不启动调查；按主入口默认交给 breach 生成包外 HTML 展示。仅问身份或单个事实不触发。目标是回答这个人如何形成并表达判断、在哪些问题上值得参考及为什么；作品收集服务于调查，不能替代结论。沿用 Dossier 的材料契约、只读调档边界与登记流程。

## 先定位对象，再沿证据扩展

- 区分作者、发布账号、被引人物、访谈主持人/嘉宾与编辑团队。转发、主持或账号归属不能让所有内容自动成为本人观点。
- 用署名、稳定账号 ID、官方互链、同题同日作品、主办方及出版记录核对身份；同名、头像相似或聚合站分类不足以直接合并。关系标明依据与置信程度；必要时仅建立作品关联，保留账号所有权未知。
- 不要求用户提供每个平台链接。按已知别名、历史署名、职业/组织、作品标题、合作方主动追踪；关键对象歧义才询问，并继续不依赖答案的查证。
- 微信等入口受限时，尝试适用的读取回退，并用可见标题、署名、账号信息找公开转载、访谈及历史记录。入口失败不等于整个调查失败；但若没有足够身份线索，明确需要哪项最小信息，不猜作者。

## 深挖的工作线

根据对象选择有用的线索，不强迫所有人都有投资、公司或预测记录。覆盖表中逐线记已读证据、缺口及排除理由。

| 工作线 | 需要判别的问题 |
|---|---|
| 身份与跨平台渠道 | 哪些是本人/团队账号，哪些是转载、访谈或第三方讨论？ |
| 职业与公开资历 | 同时代书目、任职/活动记录能否支持后来简介？头衔是否被夸大解释？ |
| 组织、合作与商业活动 | 公开课程、产品、社群、任职、赞助、投资或持仓披露与表达有什么关系？ |
| 长期观点与方法 | 不同时间/场景下哪些主张稳定，哪些改变？依据是数据、经验、类比还是价值认同？ |
| 争议、反例与修正 | 主动寻找不利于初始画像的材料、失败判断、原始认错、撤回或反对意见；不能只采纳作者自选的成功案例。 |
| 影响与外部评价 | 谁引用或与其合作？是独立佐证、同源转载、商业推荐还是利益相关者评价？ |

优先寻找同时代原始记录、本人完整表述与合作方原件，沿新线索迭代。不要在搜索到几篇代表作、一个自我介绍或固定篇数后直接收口。发现关键商业关系或历史反例，应追到能改变判断的证据层；全文批量归档不是完成调查的前提。

## 证据纪律

- 分开记录事实、本人自述、第三方评价和调查者推断。每个重要结论绑定来源、日期、定位与读取范围；当前简介不能自动证明当年状态。
- 区分本人账号、授权转载、节目文字整理、第三方评论。一个通稿在多站出现仍是一条来源链；搜索片段、机器生成摘要和标题不等于全文。
- 需提取正文时，按输入读取并复用 acquisition 的[文章提取管线](../../acquisition/references/article-pipeline.md)或[音视频提取管线](../../acquisition/references/video-pipeline.md)及 `scripts/source_identity.py`；执行身份检查、正文 gate 与相应失败回退。只复用内容取得工具，不嵌套启动另一条用户入口工作流。Dossier 继续拥有调查与综合结论：人物任务中的履历、立场和利益背景不能被单篇“干货蒸馏”规则过滤；所得原件按材料库规则归档，综合材料进入卷宗，不默认逐篇生成 query。用户另要求单篇摄入时才执行对应完整流程。
- 下载图片不等于读完图片，节目说明不等于听过访谈。若关键论点藏在图片/音视频中，应读取相关部分或明确证据缺口；未读内容不得支持画像。
- 公开合作只证明所述合作；不能直接推成任职、报酬或控制关系。认同品牌不证明持股；有商业产品不证明不诚实；没有找到披露也不证明无利益关系。
- 仅调查与公开表达、职业活动相关的公开信息。不追查无关私人生活，不用泄露资料补实名，不联系本人、加群或购买服务来完成默认流程。

## 有判断/预测时，追查事前版本

保留主张的主体、发表时间、期限、适用条件、量级和原始措辞，分清描述、价值选择、方法建议、可能情景与可检验预测。嘉宾观点、公司指引、被转述者目标不能记作作者预测。

遇到“我早就说过”“预测成功”“曾经认错”，沿标题/日期/跨站记录寻找事前原稿及修订记录，再与独立结果对照。找不到时保留“当前自述”，不能升级为已验证战绩。不得把长期市场容量改写成年份确定的销量预测，也不把不同统计口径强行作比。可指出某次论证的缺口，但完整预测集合、评价标准与结果不足时不报胜率、不由单例概括全部能力。

## 从调查形成结论

入口应让读者直接看到：

- 有证据的身份定位，以及与起初印象相比新增、推翻或收窄了什么。
- 长期立场、推理习惯、演变与重要反例；存在商业/组织场景时说明其实际含义。
- 按用途区分可信范围，例如事实整理、专业解释、需求预测、价值倡议；给出理由，不用无依据的统一评分或人格标签。
- 仍不能确定什么、查了哪些方向及为何受限；“未找到”不写成“不存在”。

材料目录随证据组织，可包含身份/关系表、观点时间线、判断台账、来源与作品清单。复用 manifest，不为人物OSINT分支增加另一套注册或强制 schema。来源数、文章数、全文数分别计数，既不以数量包装深度，也不把深挖声称为穷尽全网。

更新时保留旧结论与修正依据，但入口和当前台账必须反映最新状态；不要在最新结论后直接拼接仍宣称“原稿未找到”的旧正文，让读者自己消解矛盾。

## 收口检查

逐项检查：是否核对了对象？是否主动追踪了跨平台身份和公开关系，而非只扩充文章？是否找过反证和利益背景？重要判断是否有对应已读证据？哪些只能是暂定结论？

重要工作线已有足以形成有界判断的证据，或尝试后仍遇到具体权限/原件缺失；继续搜索只返回同源重复和低价值线索时，可以带缺口交付。若缺口可能改变核心画像，降低结论强度或保留未决，不为了“完整”猜测，也不以入口失败或材料篇数作为唯一停止理由。结构 gate 只验证材料契约，不证明 OSINT 深度或预测可靠性。
