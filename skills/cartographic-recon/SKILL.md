# Cartographic Recon — 地图侦察

将真实地点与线路转成手绘地图，负责查证、绘制、修订和交付。
`invocation: user`，`role: orchestrator`，`calls: []`。
直接使用可用的地图查询与图像工具；不嵌套其他用户级地图流程。

## 任务与工具

- 从对话取得区域、必标地点、地图范围、参考画风和现有图；已有信息不重复问。
- 区分新绘、补地点、纠错、换画风。多个候选先确定选中的版本；不能只凭文件名猜。
- 地理信息优先使用可用的高德工具。缺失时用用户给定底图或有出处的地图/官方资料；
  数据不足则标记待核实，不把推测位置画成已核实事实。
- 栅格生成和编辑使用 `imagegen` 能力及其工具约定。工具不可用时保留底稿并说明阻塞，
  不将文字提示词称为已生成地图。读取本地目标图后再编辑；分享页中的图需先实际获取。
- 用参考图片描述具体色彩、笔触、建筑、树木和光线，保持用户选定画风；
  风格名称本身不能代替参考图和视觉特征。

## 地理底稿

首次绘制前，在用户选定输出目录保存 `map-brief.md`；未指定则按任务名在当前工作区
选择目录。保留来源引用与版本身份，不复制无关会话产物。

底稿只记录本图需要的关系：

- 范围、朝向、等比例或示意图、参考图绝对路径/URL。
- 必标地点的稳定 ID、名称、来源、坐标及坐标系（有数据时）、核验状态。
- 与道路/绿道的左右或东西关系、街区顺序、关键路口、必保留连接。
- 需要保留的分支、平行道路、桥或跨越关系。线路不是全部直连 POI 的折线；
  距离和全长不能推出完整线路形状，不拼接未核实的缺段。
- 长度与边界的来源：区分用户指定、官方项目长度和查询路线长度；不同范围不能混用。
- 可变项：画风、装饰、建筑外观、标注疏密；不变量：已核实的位置、顺序、连接、名称。

记录地点坐标不能证明道路连接；生成器声称“保留路网”不能作为核验证据。
新地点含歧义且会改变图中位置时才澄清。示意图允许压缩距离，但仍须保留约定的
方位、顺序与连接。不将用户家庭地址、实时位置或完整行程主动写入 Canon。

## 绘制与修订

1. 对照底稿检查遗漏、互相矛盾的关系与未核实项，先解决影响主线结构的问题。
2. 将明确地理骨架和画风参考交给生成器；少选地标，给道路与文字留空间。
   要求结构严格准确时，考虑固定可编辑底图、仅生成装饰；不得承诺自由生成能保证拓扑。
3. 补地点或纠错：以已选图为编辑目标，只改受影响区域；换画风：明确保留全部地理关系。
   不因改画风重新猜测位置。每次修改同时检查既有正确内容是否退化。
4. 输出使用版本化文件名，不覆盖已接受的图。更新底稿中的当前版本及变更点。

## 交付门禁

实际查看最终图后，对照底稿记录 `map-check.json`。最小结构：

```json
{
  "artifact": "/absolute/path/map-v2.png",
  "brief": "/absolute/path/map-brief.md",
  "previous_artifact": null,
  "verdict": "pending",
  "checks": [
    {"id": "critical-junction", "status": "pending", "evidence": "", "finding": ""}
  ]
}
```

`checks` 按本图实际不变量展开；每项 `status` 为 `pass|fail|pending`。
检查地点方位/街区、关键线路连续性与分支、交叉口对齐、名称可读性和遮挡、参考画风；
编辑时加上未修改区域的回归检查。`evidence` 指向查看的图、底稿关系或查询来源；
这是 agent 的检查记录，不是自动几何认证。未查看图片时视觉项保持 `pending`。

- 任一必需项 `fail` → `verdict: fail`；无失败但存在待核实项 → `pending`；全部必需项
  经实际检查通过才用 `pass`。无法核实的事实不靠生成器解释消除。
- 有具体缺陷时局部修正；每次修订重新检查该版本。默认最多连续修正两轮，仍失败则
  交付标明问题的草稿和缺口，不把它说成准确成品；用户指定修订范围时遵从用户。
- 交付选中的图、底稿、门禁记录；简述版本、主要修改和未核实项。非等比例图注明
  示意性质，不把“第二张”或“更漂亮”当作准确度证明。
